# 部署与交付

面向目标用户的命令见 [安装使用说明](usage.md)。智能体制作、测试及归档的完整流程见 [操作手册](agent-playbook.md)、[测试方案](test-plan.md) 与 [构建与发布](build-release.md)。

## 推荐过程

1. 在开发机补齐版本、离线安装包、SHA256、参数和验证条件。
2. 预演确认顺序，再运行 `Start.ps1 -Profile <方案> -Validate`。预检对全部选中插件执行，后项缺包也会阻止前项安装。
3. 在测试机逐插件执行，检查日志、版本、功能、用户/机器范围和新终端 PATH。
4. 测试完整方案，包括失败停止、已安装版本、重启后继续和离线运行。
5. `scripts/Build.ps1 -Profile <方案>` 生成交付目录与 ZIP。
6. 复制整个 ZIP 到目标机，解压至本地可写的英文目录，如 `D:\AutoDeploy`，允许空格。不要直接在压缩包内运行；路径过长时换短目录。官方 Au3Check 对中文工作区路径的 include 解析存在限制，详见环境说明。
7. 双击 `Run.cmd` 只预演。命令行运行 `Run.cmd -Validate` 进行预检；明确安装时使用 `Run.cmd -Execute`。Git/MSI 方案通常需要从管理员终端启动。

开发机可先用 `scripts/Build.ps1 -Profile empty` 验证打包；empty 不含业务软件，只验证交付结构。

沙盒迭代可用 `scripts/Build.ps1 -Profile dev -SkipArchive` 只生成目录，节省反复压缩时间；最终交付省略该开关以同时生成 ZIP。

当前 `dev` 顺序为 Git、uv、VC++ x64 运行库、rustpm MSI。`-Only` 不自动补齐依赖，单测 MSI 前必须先安装或验证 `vc-runtime-x64`。正式安装入口不会修改 Windows 代码完整性策略；Sandbox 的可选兼容开关只作用于一次性测试环境。

## 执行语义

- 预演不下载、不安装、不修改用户 PATH，不会运行软件验证命令。
- `-Validate` 校验运行时、版本配置和包摘要，不执行安装，也不要求已安装的软件文件存在；不会自动修复配置。
- `-Execute` 严格按顺序运行。失败或安装后验证失败立即停止，剩余项保留 `pending`。
- 3010/1641 会停止队列并记录 `reboot-required`，尚未执行安装后验证。完成重启后验证该项，再从后续插件继续；不要自动重复整个方案。
- 超时退出 124。实际安装器可能仍在运行，先根据 `module.log` 中 PID 与厂商日志检查状态，再决定后续操作。
- 执行器不会自动回滚、卸载、杀死安装进程树或自动重试。
- 同一工作区通过锁文件拒绝并发安装；不要从多个独立交付目录同时操作同一台目标机。
- `skipIfVerified=false` 默认会再次运行所选安装器。启用跳过前，先配置并验证准确版本的检查条件。

## 日志

每次显式执行产生 `logs/<时间>-<唯一后缀>/`，包含 `results.json` 和每个插件的日志目录。成功状态为 `installed-verified` 或 `skipped-verified`；还可能出现 `failed`、`reboot-required`、`pending`。

MSI 详细日志为 `msi.log`，Git 为 `git-setup.log`，uv 为 `uv-install.log`。uv 解压中间文件保留在该插件日志目录，便于诊断，可在确认安装结果后按实际目录清理。

日志可能包含用户名、路径及厂商输出，分享前检查敏感信息。没有输入实际安装包之前，只能证明工具链/执行链有效，不能宣称软件安装已验证。

## 交付内容

构建只选中一个方案及其插件配置和主安装包，同时携带 `scripts/`、文档及完整 AutoIt `install/`。不包含开发机日志或其他方案安装包。构建重新校验主安装包并生成 `bundle-manifest.json`，记录交付文件 SHA256；该清单用于完整性核对，不是数字签名。

新建交付方案只需要新清单；若同软件需要不同参数或版本，可复制为不同 ID 的插件配置，再复用相同 AutoIt 模块。当前清单中每个 ID 只能出现一次。

正式发布前至少覆盖：干净 Windows 目标机、指定旧版本升级场景、安装路径带空格、预期账户权限、网络断开、重启状态及失败恢复。真实业务安装测试不在本次工作区初始化中执行。
